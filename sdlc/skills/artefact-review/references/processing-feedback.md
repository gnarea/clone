# Processing feedback

Feedback can come in any format (e.g., a report, comments on a pull request, a chat message), so you MUST first break it down into individual findings.

Whoever raised a finding, you MUST judge it against the requirements, the conventions, and your priorities. You MUST NOT accept a finding to be agreeable, nor dispute one to spare yourself work.

You MUST address each finding that you agree with. Where a finding prescribes a fix, you MAY address it differently.

You MUST dispute each finding that you disagree with, giving reasons that can be checked (e.g., the requirement that it contradicts, the evidence that its consequence can't happen).

Where a finding is ambiguous, you SHOULD act on a reasonable interpretation of it, and state that interpretation in your reply.

Addressing a finding is a change like any other, so it requires confirmation wherever the /sdlc:escalation skill says so.

Where a finding that you've disputed is raised again and you still disagree, you MUST escalate the disagreement, laying out both positions, rather than dispute it again.
